# Dedicated AVX-512 experiment

This separate 0.2.0 codebase adds a sixteen-lane i32 DP kernel behind the `avx512` Cargo feature. The original `minipoa-rs` AVX2/NEON deliverable remains separate. The AVX-512 kernel processes sixteen match/deletion scores and affine-gap transitions at a time, including a four-stage prefix scan across all sixteen lanes. Eight-column band boundaries and exact eight-lane tails preserve compatibility with the existing kernel. The score-overflow guard, reusable arenas, Rayon pool, minimizer extraction, and scalar i64 fallback remain available.

## Run the Linux experiment

Requires x86_64 Linux, Rust 1.89 or newer, Python 3, and CPU/OS support for **AVX2, AVX512F, and AVX512BW**. The `wide` 1.7.1 dependency requires F+BW together for this native build, even though the core score operations use AVX512F.

From the extracted source directory:

```sh
bash scripts/test_avx512_linux.sh --rounds 5 --cases 100
```

The driver checks the host CPU flags, builds separate AVX2 and AVX-512 executables, runs their release test suites, checks backend metadata, compares exact consensus/MSA/GFA output, and records interleaved whole-program timings for one-thread and four-thread runs. It downloads no C++ source. To also compare with your existing C++ minipoa:

```sh
bash scripts/test_avx512_linux.sh --rounds 5 --cases 100 --cpp /absolute/path/to/minipoa-cpp
```

Results default to `target/avx512-experiment/backend-comparison.json`; an optional C++ comparison is written to `cpp-differential.json`. The directory also contains compiler and CPU details. Use `--output-dir PATH` to choose another destination, or `--rounds 0` to skip timings. `AVX2_RUSTFLAGS` and `AVX512_RUSTFLAGS` can override the recorded default flags.

## Build only the AVX-512 executable

```sh
export CARGO_TARGET_DIR=target/avx512
export RUSTFLAGS="-C target-cpu=x86-64 -C target-feature=+avx2,+avx512f,+avx512bw"
cargo build --release --locked --features avx512
./target/avx512/release/minipoa --version
./target/avx512/release/minipoa --input reads.fasta -S -t8 > consensus.fasta
```

The Rust executable requires `--input PATH` (or `--input -` for stdin). It uses clap 4.5 with `--help` and `--version`; existing short options and legacy underscore long-option aliases remain available. The comparison scripts pass `--input` to Rust and a positional path to upstream C++.

The version output must include:

```text
DP backend: avx512-native (16 x i32)
```

Alternatively, `RUSTFLAGS="-C target-cpu=native"` works when building directly on a compatible AVX-512 machine. The comparison driver uses controlled flags for both executables and disables LTO equally, so its AVX2 baseline does not accidentally enable AVX-512.

These are CPU-specific builds, with no runtime ISA dispatch. Execute the AVX-512 executable only on a compatible host. Extreme scores may fall back to scalar i64 inside the program, but that does not make an AVX-512-compiled executable portable to CPUs without AVX-512.

## Inspect the dedicated kernel

On Linux, GNU objdump can show the generated wide instructions:

```sh
objdump -d -C target/avx512/release/minipoa | grep -E 'vpmaxsd.*zmm|vpaddd.*zmm|vpermi2d.*zmm|vpermt2d.*zmm'
```

A sixteen-lane feature build without AVX512F uses `wide`'s portable representation. Its version reports `avx512-portable`; that is useful for correctness testing but is not a native AVX-512 performance measurement.

## Local validation scope

See [AVX512-VALIDATION.md](AVX512-VALIDATION.md) for results. Portable sixteen-lane execution has been checked on ARM, and the Linux AVX-512 build has been cross-compiled and inspected for native ZMM instructions. Native AVX-512 execution and speed have not been measured locally. Your Linux experiment is needed for those results; a sixteen-lane kernel is not assumed to be faster on every CPU or workload.
